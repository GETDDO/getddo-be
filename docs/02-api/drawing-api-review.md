# 추첨 API 구성 검토

- 상태: 검토 대기 — 담당자 확인 전
- 범위: 추첨 실행·결과 확인·당첨 취소·재추첨·공개
- 경로는 검토용 제안이며 공용 API 계약을 확정하거나 대체하지 않는다.
- 정책 기준: `getddo-spec/02-domain/drawing.md`

현재 확정 정책은 최초 추첨·발표는 자동, 당첨 취소에 따른 재추첨은 관리자 요청, 재추첨 결과 공개는 관리자 확인 후다.

기본 경로는 `/api/v1`이며, 아래 표에서는 생략했다.

## 사용자용 API

| 기능 | 메서드·경로 | 필요한 이유 |
| --- | --- | --- |
| 이벤트 결과 조회 | `GET /events/{eventId}/results` | 발표 여부와 경품별 공개 당첨자 확인 |
| 내 결과 조회 | `GET /events/{eventId}/my-result` | 본인의 당첨·낙첨·취소 여부와 경품 확인 |

공개 전에는 당첨 정보를 숨기고, 발표 예정 시각과 대기 상태를 제공한다.

## 관리자용 API

| 기능 | 메서드·경로 | 필요한 이유 |
| --- | --- | --- |
| 추첨 목록 조회 | `GET /admin/events/{eventId}/draws` | 최초 추첨과 재추첨 이력 확인 |
| 추첨 상세 조회 | `GET /admin/draws/{drawId}` | 진행 상태, 적용 조건, 경품별 결과, 실패 정보 확인 |
| 추첨 대상 조회 | `GET /admin/draws/{drawId}/participants` | 당시 후보와 응모권 수·가중치 확인 |
| 결과 정합성 검증 | `POST /admin/draws/{drawId}/checks` | 후보·조건·결과가 일치하는지 검증 |
| 검증 이력 조회 | `GET /admin/draws/{drawId}/checks` | 검증 결과와 검증자·시각 확인 |
| 당첨 취소 | `POST /admin/wins/{winId}/cancellations` | 취소 사유를 기록하고 당첨 취소를 확정 |
| 재추첨 시작·재개 | `POST /admin/cancellations/{cancellationId}/redraws` | 해당 취소로 빈 경품 자리의 재추첨을 시작하거나 실패한 동일 실행을 재개 |
| 재추첨 결과 공개 반영 | `POST /admin/draws/{drawId}/publication` | 관리자가 확인한 새 결과를 공개 명단에 반영 |
| 공개 명단 변경 이력 조회 | `GET /admin/events/{eventId}/result-changes` | 변경 전후 당첨자·경품·처리자·사유 확인 |

## 당첨 취소 이후 흐름

```text
관리자가 당첨 취소 요청
→ 서버가 당첨 취소를 확정하고 연결된 재추첨 작업을 함께 등록
→ 서버가 등록된 작업으로 재추첨을 즉시 시작
→ 빈 경품 자리만 재추첨
→ 관리자가 추첨 상세에서 결과 확인
→ 공개 반영 요청
→ 사용자 결과 조회에 새 명단 반영
```

당첨 취소와 재추첨 시작·재개는 별도 API로 구분한다. 버튼을 따로 둘 필요는 없으며, 프론트엔드의 연속 호출만으로 두 처리를 연결하지 않는다. 서버는 취소 확정과 재추첨 작업 등록을 함께 보장하고 등록된 작업의 즉시 실행을 책임진다. 작업 등록·실행의 구체적인 구현 방식은 이 문서에서 정하지 않는다.

재추첨 API는 확정된 취소 건에 연결된 작업의 시작·재개 용도다. 서버의 자동 실행과 API 호출이 겹치거나 같은 요청이 반복돼도 하나의 재추첨 실행만 사용한다. 진행 중이면 기존 진행 상태를 반환하고, 완료됐으면 저장된 결과를 반환하며, 실패한 동일 실행의 재개를 새 재추첨으로 기록하지 않는다.

기존 유효 당첨자와 경품은 유지한다. 취소 요청 재시도는 기존 취소 기록을 반환하고 재추첨 작업을 중복 등록하지 않는다. 공개 반영 재시도도 명단을 중복 변경하지 않는다.

## 별도 API가 필요하지 않은 처리

최초 추첨 실행·최초 발표 승인·자유로운 재추첨 API는 필요하지 않다. 최초 추첨과 발표는 서버 내부 자동 처리이고, 현재 정책상 재추첨은 확인된 당첨 취소에 연결된다.

사용자 2개·관리자 9개를 기준으로 각 API의 입력과 응답을 정한다.
