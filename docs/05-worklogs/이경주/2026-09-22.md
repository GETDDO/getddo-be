## 고민과 판단

- sapari의 구성을 참고해 Spring MVC 매핑과 DTO 타입으로 문서를 생성하는 방식을 선택했다. `@Tag`, `@Operation`, `@Schema`는 기본 문서 생성에 필수로 두지 않고, 설명을 보강할 때 선택적으로 사용한다.
- 현재 업무 Controller와 사용자·관리자 경로 규칙이 없어 통합 문서 하나로 시작했다. 그룹 분리는 실제 API 경로가 정해진 뒤 적용한다.
- `ResponseEnvelope<실제 응답 DTO>`의 `data` 구조까지 문서화되는지 검증했다. 실행 중 결정되는 업무 오류 코드와 모든 오류 응답은 자동 추론만으로 문서화되지 않으므로 이 한계를 사용 안내에 적었다.
- 로컬 실행을 위해 임시로 추가했던 DB 설정은 요청에 따라 최종 변경에서 제외했다. 실제 애플리케이션 실행에는 별도의 DB 연결 준비가 필요하다.
