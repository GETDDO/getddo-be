## 고민과 판단

- 테스트 DB도 MySQL로 통일하되, 초기 세팅에서는 SQL 적용·재실행과 기존 검증을 유지하는 데 집중했다. 도메인별 제약조건·트랜잭션 검증은 해당 기능을 구현할 때 추가한다.
- API 테스트는 같은 컨텍스트 안에서만 DB를 공유한다. 테스트 전용 테이블을 생성하는 Entity 테스트와 실제 SQL을 적용하는 Flyway 테스트는 분리해 서로 영향을 주지 않게 했다.
- PR의 `edited` 이벤트를 전부 제거하면 병합 대상 변경도 검증하지 못하므로, 실제 변경 필드를 확인해 제목·본문 변경만 제외했다.
- 자동 포매터·`.editorconfig`·파일당 200줄 강제 규칙은 사용자의 최종 의사에 따라 도입하지 않았다. 코드 스타일 가이드 전체를 확정한 작업도 아니다.
