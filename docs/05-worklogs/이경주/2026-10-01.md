## 고민과 판단

- 여러 기능이 함께 호출하지만 자체 저장 모델과 책임이 있어 `common` 대신 독립 `audit` 패키지를 사용한다. 사용자와 패키지 배치를 확인한 뒤 구현했다.
- 사용자 검토 후 최신 `dev`의 core 모델 규칙에 맞춰 `AuditLogCommand`를 `final class`와 `private final` 필드로 정리했다. Lombok `@Getter`로 `getXxx()` 접근자를 제공하고 명시적 생성자에서 필수값·길이 검증과 변경 전후 데이터의 중첩 방어적 복사를 수행한다. 값 비교가 필요한 사용처가 없어 `equals`·`hashCode`는 재정의하지 않는다. record 예외를 추가하지 않고 백엔드 컨벤션을 따른다.
- 계획의 추천안대로 업무 트랜잭션에 참여하는 `MANDATORY`를 적용했다. 감사 저장 실패는 전파하고 업무 변경과 함께 rollback한다. 반환 UUID만으로 commit 성공을 의미하지 않는다.
- 작업 코드·대상 명칭·전후 필드는 소비 기능의 확인 대상이며 이번 기반에서 enum이나 실제 업무 정책을 확정하지 않았다. requestId는 선택 입력으로 두고 추적 필터·중복 방지 기능을 추가하지 않았다.
- 기존 V011·BaseEntity·사용자 모델·공통 오류·의존성을 변경하지 않았다. 기존 storage 런타임에 Jackson 3가 포함돼 JSON 매핑을 사용할 수 있었다.
- GD-54를 축소한 대화에 따라 감사 사용 문서의 색인 링크는 GD-55에서 함께 연결했다.
