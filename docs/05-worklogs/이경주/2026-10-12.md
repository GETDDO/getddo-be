## 오늘 한 일

- [GD-168](https://ureca4.atlassian.net/browse/GD-168)의 최종 범위를 사용자 모델 컨벤션 정리로 축소했다.
- `User` record를 `private final` 필드·명시적 생성자·`@Getter`를 사용하는 불변 클래스로 전환했다. `@EqualsAndHashCode`는 사용하지 않는다.
- 사용자 모델 소비 코드의 접근자 호출을 getter로 바꾸고, DB 조회 테스트는 객체 동등성 대신 필드 값을 비교하게 수정했다.
- 최신 `dev`의 응모 Controller·테스트에 남은 기존 접근자 7곳을 수정하고, 생성자의 `id`, `name`, `role`, `status`에 null 검증을 추가했다. 나머지 필드의 기존 null 허용은 유지했다.
- 기존 역할·멤버십 헤더 검증과 비활성 사용자의 내 정보 조회 `403 / USER-007`을 유지했다.
- 기능 변경은 `6de3006`까지 푸시해 [PR #60](https://github.com/GETDDO/getddo-be/pull/60)에 반영했다. 리뷰 코멘트 3건에 수정 결과와 동등성 구현·문서화 방침을 답글로 남겼다.

## 고민과 판단

- 사용자가 프론트엔드에서 명단을 관리하고 DB 계정은 나중에 직접 입력하기로 했다. 백엔드는 기존 요청을 처리한다.
- 이에 따라 이전 커밋의 목록 API·응답 DTO·서비스 고정 명단·시연 SQL과 해당 기능 전용 테스트를 제거했다.
- 다른 담당 영역은 User 접근자 호출만 바꾸며 업무 로직이나 공개 API 계약을 변경하지 않았다.
- 작업 로그는 GD-168 기능 커밋에서 제외해 로컬에 보존했다가, 사용자 확인 후 날짜별 공용 워크로그 PR #55에서 별도로 공유한다.
