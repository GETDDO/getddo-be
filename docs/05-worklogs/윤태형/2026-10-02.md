## 오늘 한 일

### 응모권 배분·게임 통계 테이블 단일 PK 전환 (GD-88)

- 2026-10-01 ERD 회의 결정에 따라 복합 PK였던 `ticket_ledger_allocations`와 `user_game_stats`를 단일 `id`(BINARY(16)) PK로 바꿨다. 기존 PK 조합은 `uq_ticket_ledger_allocations_1`, `uq_user_game_stats_1` UNIQUE로 남겨 중복 방지는 유지한다. 이제 41개 테이블이 모두 단일 `id` PK다.
- 배분 Entity는 `@IdClass`를 없애고 원장과 같은 `@UuidGenerator(VERSION_7)` id를 쓴다. `TicketLedgerAllocationId`를 삭제했다. `created_at`은 지금처럼 지급 시각을 직접 채운다(ADR-0001 예외 유지).
- `docs/03-database/schema.dbml`의 두 테이블 정의를 맞췄다.

## 고민과 판단

- **V005·V008을 직접 수정했다.** 아직 어떤 DB에도 적용되지 않은 초기 DDL이라 새 V012 대신 기존 파일을 고치는 팀 관행을 따랐다(담당자 승인). AGENTS.md의 "기존 Flyway 마이그레이션 수정 금지"와 다르다.
- **도메인 `TicketLedgerAllocation`에 id를 노출하지 않았다.** 배분은 쓰기 전용이고 읽어서 도메인으로 바꾸는 곳이 없다. 차감·만료에서 배분을 읽게 되면 그때 추가한다.
- 두 테이블을 FK로 참조하는 테이블은 없고, `user_game_stats`는 Java 코드가 없다. getddo-spec에는 수정할 내용이 없다.
