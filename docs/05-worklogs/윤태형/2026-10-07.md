## 오늘 한 일

### 응모권·출석·미션 ERD 정리 (GD-93, PR #26)

- 최신 상태를 반영했다. `getddo-spec`에는 출석 브론즈 확정(ADR-016)과 회수 제외(ADR-017)가, `getddo-be` `dev`에는 PR #26 병합이 들어왔다.
- 응모권을 `tickets`(현재 상태)와 `ticket_histories`(수정 없이 쌓는 이력) 두 테이블로 보는 구조를 검토했다. 지급 근거 claim FK 3개는 `tickets`에 두고 `grant_seq`는 뺐다. 중복 지급은 미션·게임 claim UNIQUE로, 출석은 출석 claim UNIQUE와 지급 호출 규약(claim 저장과 지급을 한 트랜잭션)으로 막는다.
- 최신 DBML과 마이그레이션 V003~V006의 UNIQUE를 컬럼 조합 단위로 비교했다. 마이그레이션에 새로 넣어야 하는 UNIQUE는 10개이고, `mission_submissions`의 멱등 키 UNIQUE 1개는 해당 컬럼을 되살릴 때만 필요하다.
- PR #26 브랜치에 `tickets.grade`를 `NOT NULL`로 바꾸는 커밋(5d5b488)을 올렸다. PR #26은 이후 병합됐다.

### 동시성 통합 테스트 보강 (GD-96, PR #25)

- CodeRabbit 지적에 따라 `ConcurrentTasks.shutdownAndAwait`를 고쳤다. 기다리는 도중 현재 스레드가 interrupt되어도 작업 스레드에 interrupt를 보내고 남은 제한 시간 안에서 종료를 계속 기다리며, 돌아오기 전에 interrupt 상태를 복원한다. 예외를 직접 처리하므로 `throws InterruptedException`을 뺐다.
- DB 없이 종료 대기를 검증하는 `ConcurrentTasksTest` 2개를 추가했다. 커밋 baf0b65.

## 고민과 판단

- 확정된 정책은 스펙을 따른다. 출석 보상은 브론즈 고정([ADR-016](https://github.com/GETDDO/getddo-spec/blob/main/03-decisions/016-attendance-bronze-tickets.md)), 부정 획득 응모권 회수 기능은 제외([ADR-017](https://github.com/GETDDO/getddo-spec/blob/main/03-decisions/017-exclude-ticket-recovery.md))다.
- 아래는 담당자가 정했지만 스펙에 아직 반영되지 않은 결정이다.
  - 기존에 지급된 무등급 응모권이 있다면 일괄 브론즈로 전환한다. 현재는 없다고 가정한다.
  - 응모할 때 등급별 장수는 사용자가 선택한다.
  - 반환할 때 등급은 보존한다. 같은 티켓 행을 재사용하고 등급은 지급 후 바뀌지 않는다.
  - 부정 확정으로 제외돼도 응모에 쓴 응모권은 반환한다. 회수를 제외했으므로 별도 몰수는 하지 않는다.
  - 가중치 없는 이벤트의 1회 응모 제한은 `event_participants`의 `UNIQUE(event_id, user_id)`와 앱 규칙으로 보장한다.
- PR #26의 CI 실패는 이번 변경이 아니라 동시성 통합 테스트의 불안정으로 판단했다. 같은 코드가 앞 실행에서는 통과했다. 이 워크플로는 같은 PR에서 이전 실행을 취소하므로, 이전 커밋의 빌드를 재실행하면 새 커밋의 빌드가 취소될 수 있다.
