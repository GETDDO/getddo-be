## 오늘 한 일

### 응모권·출석 도메인 `@EqualsAndHashCode` 제거와 출석 `refresh` 정리 (GD-94)

- 응모권·출석 core 도메인 21개 클래스에서 `@EqualsAndHashCode`를 뺐다. 운영 코드는 도메인 객체의 `equals`를 쓰지 않고, JPA가 요구하던 복합 키 클래스는 GD-88에서 없어졌다.
- 테스트는 PR #18처럼 값을 비교하는 방식으로 바꿨다.
  - 객체 비교: `usingRecursiveComparison()`
  - 목록 비교: `usingRecursiveFieldByFieldElementComparator()`
  - 같은 객체 반환 확인: `isSameAs`
  - 서비스 안에서 새로 만드는 인자의 Mockito 매칭: `refEq`
- PR #18로 Auditing 시각이 마이크로초로 잘리게 되어, 출석 저장 직후의 `refresh`와 쓰지 않게 된 `EntityManager` 필드를 지웠다.

## 고민과 판단

- 앞으로 값 객체를 `Set`·`Map`·`contains`에 쓰면 그 클래스에만 `equals`·`hashCode`를 다시 구현한다. `code-style.md`와 ADR-0002는 "값 비교가 필요하면 구현"이라는 조건부 규칙이라 고치지 않았다.
- 같은 인스턴스끼리 비교해서 통과하던 단언은 의도대로 두었다. 연속 현황이 역순 날짜에서 자기 자신을 돌려주는지 보는 단언은 `isSameAs`로 바꿔 의도를 드러냈다.

## 확인 결과 / 막힌 점

- 제거 직후 실패한 테스트는 core 8, `storage:db` 통합 12건이었고, 비교 방식을 바꾼 뒤 모두 통과했다. 단언을 지우거나 비교 필드를 줄이지 않았다.
- `./gradlew build --rerun-tasks` 통과. core 150, `storage:db` 통합 79, api 단위 109, api 통합 31개, 실패 0. 테스트 수는 변경 전과 같다.
- `refresh` 제거 후 "시계가 나노초를 주어도 첫 응답과 같은 날 재요청의 출석 기록 시각이 DB 저장 값으로 같다" 통합 테스트가 통과했다.
