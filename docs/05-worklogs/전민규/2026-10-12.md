## 고민과 판단

- 수동 복구는 기존 알림 ID·읽음 상태를 유지하고 누적 처리 차수를 초기화하지 않는다. 새 구간의 기준 차수로 재시도 횟수를 계산하고 늦은 워커 결과를 구분한다. 구현 근거는 [ADR-0005](https://github.com/GETDDO/getddo-be/blob/dev/docs/04-decisions/0005-notification-manual-retry-fencing.md)에 제안 상태로 기록했다.
- 공통 모델 변경을 반영하기 전 서비스 호출만 변경하면 로컬 빌드도 깨질 수 있었다. User 버전과 호출부를 함께 맞춘 뒤 관련 테스트 소스까지 컴파일했다.
- 테스트 준비가 전역 작업을 선택하면 실행 순서에 따라 다른 작업을 처리할 수 있으므로 지정한 ID의 준비와 실제 워커 선점 검증을 구분했다.
