### 오늘 한 일

- E01·E02 사용자 이벤트 목록·상세, AE01·AE02 관리자 이벤트 목록·상세를 구현했다. 기존 `ResponseEnvelope`, `PageResult`를 사용하며 API 응답은 DTO의 `from(...)`으로 변환한다. Entity→core 변환은 기존 MapStruct를 유지한다.
- 사용자 목록은 상태·유형·최소 멤버십 설정, 관리자 목록은 제목 키워드·상태·유형·기간으로 필터링한다. 페이지는 1부터, 기본 크기는 20, 허용 크기는 1~100이다.
- `@CurrentUser`로 확인한 DB 사용자를 조회 서비스에 전달해 활성 상태·관리자 권한을 검사한다. 기본 사용자 문맥 규칙에 따라 USER의 멤버십 헤더는 필수로 대조하며 ADMIN에게는 요구하지 않는다.
- 조회 포트와 네이티브 SQL 구현을 분리했다. 공통 WHERE 절을 목록과 전체 건수에 적용하며 정렬은 `created_at DESC, id DESC`다. 관리자 목록의 경품은 페이지 ID로 일괄 조회하고 사용자 목록에서는 경품 쿼리를 생략한다. 상세 경품은 등수 오름차순이다.
- 사용자 응답에서 이미지 키·생성자·운영 메타데이터를 제외하고, 관리자 응답은 중단 이전 상태·중단/취소 시각·이미지 키도 읽는다. `deleted_at`이 있는 이벤트는 두 조회 경로에서 모두 제외하며 상세는 404로 처리한다.
- 조회 서비스는 공통 `User`를 사용한다. 등록용 `Actor`는 불변 클래스로 정리하고 기존 등록 트랜잭션 안의 관리자·활성 상태 검사를 유지한다. DB 멤버십 대소문자 변환을 보완했다.
- core의 이벤트 입력·결과 모델을 불변 클래스로 정리하고 `EventException`으로 이벤트 업무 예외를 묶었다. API 응답 매퍼를 제거하고 사용자·관리자 공용 `PrizeResponse`를 분리했다.
- 등록 기간을 저장 전 마이크로초 정밀도로 정규화하고, 등록·조회 모두 UTC 저장 지원 범위를 검사한다. 같은 정규화 시각으로 등록 상태와 저장·응답 값을 결정한다.

### 고민과 판단

- 관리자 기간 필터의 기준은 구현 전 담당자에게 확인했다. 시작 시각만 비교하는 방식 대신 모집 기간과 검색 구간의 겹침을 선택했으며, `ends_at > from`, `starts_at < to`로 처리한다. 한쪽 경계 생략도 허용하며 검색 경계에 맞닿기만 하면 제외한다.
- 2026-10-01 담당자 요청에 따라 관리자 검색의 `from`·`to` 입력을 시각에서 `YYYY-MM-DD` 날짜로 변경했다. 양끝 날짜를 포함하며, 기존 `TimeProvider`로 KST 시작일 자정과 종료일 다음 날 자정을 UTC로 변환해 위 겹침 조건에 전달한다. 같은 날짜는 하루 검색, 한쪽 생략은 단일 경계 검색이다. 날짜·시각을 혼용하지 않으며 Swagger 입력도 날짜 형식으로 안내한다. 이벤트 등록의 시작·종료 시각 입력은 유지한다.
- 담당자 확인에 따라 사용자 공개 상태는 재추첨 중 발표 기록이 있으면 `PUBLISHED`, 없으면 `DRAW_CONFIRMED`로 조회한다. 관리자에게는 실제 운영 상태를 반환한다. 같은 공개 상태 식을 사용자 목록의 상태 필터에도 적용한다.
- 발표 기록 `publications`은 읽기만 한다. 이번 조회의 `prizes`는 등록한 경품 구성이고 실제 당첨 명단이 아니다. 당첨 결과 조회·재추첨 결과 공개·취소자의 중간 표시는 추첨 담당 영역이며 이번 작업에서 변경하지 않았다.
- 제목 검색의 `%`, `_`, `!`는 검색 패턴이 아닌 실제 문자로 취급하고 모든 검색 값은 SQL 파라미터로 바인딩한다.
- S3 연동 보류 결정에 따라 조회 응답의 `imageUrl`도 `null`이다. DB 스키마·Flyway·공용 spec은 변경하지 않았다.
