## 고민과 판단

- 자체 리뷰 당시 정상 조회·등록 흐름에서 기능 오류는 발견하지 않았다. `EventView` 필수 값의 null 생성 방어, 등록 요청자 모델의 사용하지 않는 멤버십 조회, 사용자 공개 상태 필터의 CASE 평가 비용, 날짜 예외 변환 시 원인 예외 보존을 보완 대상으로 판단하고 이후 리뷰 1~4번 수정에 반영했다.
- `EventTimeRange`의 상한 `.499999`는 MySQL 8.4 공식 DATETIME 지원 범위와 일치한다. [공식 문서](https://dev.mysql.com/doc/refman/8.4/en/datetime.html)를 확인했다.
- 공개 상태 필터의 CASE를 직접 상태 비교와 재추첨 조건으로 나누는 개선 방향은 타당하다. 현재 목록 인덱스에는 status가 없어 즉각적인 성능 개선을 보장하지 않으며, 기존 삭제 조건·정렬용 인덱스까지 사용할 수 없다는 의미는 아니다. 추가 인덱스 여부는 실제 데이터와 실행 계획을 확인한 뒤 판단한다.
