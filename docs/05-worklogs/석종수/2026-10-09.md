## 고민과 판단

- 사용자와 사용 이력 집계(A), 응모별 검증 후 누적 대조(A), D 구현을 기다리지 않는 추첨 측 구현(A), 두 정상 종료 상태(A)를 정했다.
- 응모권의 현재 상태로 필터링하면 사용 당시 근거가 누락될 수 있어 응모 ID에 연결된 USE 이력을 읽는다. 등급은 불변 컬럼이며 후보 스냅샷에 등급별 장수·적용 가중치·사용 이력을 보존한다.
- 제외 저장 방식 결정은 사용자 요청으로 보류했다. 연결 인터페이스를 두고 실제 빈이 없을 때 EXCLUSION_UNAVAILABLE로 차단한다. 전원 허용하는 임시 운영 처리는 추가하지 않았다. 응모자 없는 정상 종료는 제외 조회 없이 가능하다.
- 응모·사용 이력·응모자는 세 일괄 조회로 가져온다. 기존 JDBC 관례를 재사용하고 JSON 왕복에는 BOM으로 관리되는 Jackson 3 의존성을 storage:db에 추가했다.
- 정상 종료에서 이벤트의 사용자 노출 상태는 바꾸지 않는다. 후속 실행·공개 흐름에서 연동해야 하며 이번 작업의 내부 실행 상태와 구분한다.

- 기본 Java가 없어 기존 `/tmp/getddo-jdk21`을 사용했다. 기본 샌드박스의 Gradle 캐시 잠금·소켓 제한 때문에 승인된 실행 환경에서 기존 캐시와 `--offline`으로 검증했다.
- 최초 GD-84 단위 테스트 13개와 제외 기본 설정 테스트 2개는 통과했다. 이후 마감 경계·중복 응모 검증을 추가했다.

- `git diff --check`와 변경 Markdown의 로컬 링크 검증을 통과했다. 기존 마이그레이션 본문은 변경하지 않았다. 공유·운영 DB 적용, 커밋·push 및 Jira 상태 변경은 수행하지 않았다.
