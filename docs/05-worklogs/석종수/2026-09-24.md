## 고민과 판단

- `event_entries`의 `REJECTED` 기록에는 거절 코드를 남긴다. 전용 코드가 없는 업무상 거절은 `OTHER`와 기존 `rejection_reason`에 구체적인 사유를 기록한다. 예상 밖의 서버 오류는 업무상 응모 거절과 구분한다.
- `event_entries`의 시각 컬럼은 모두 유지한다. `requested_at`은 요청 수신, `processed_at`은 성공·거절 결과 기록 시각이다. 성공 시 `accepted_at`에 `processed_at`과 같은 확정 시각을 기록하고, 거절 시 `accepted_at`은 NULL로 둔다.
- `draw_runs`가 실패하면 같은 행에서 재시도하고 `run_number`를 유지한다. 새 재추첨 실행을 만들 때마다 새 행의 `reason`에 해당 업무상 사유를 기록하며, 시스템 오류는 재추첨 사유와 구분한다. 실패 시도별 이력을 어떻게 보존할지는 추후 결정한다.
- `draw_runs`는 `READY`에 들어갈 때 후보와 추첨 조건을 확정하고 `snapshot_fixed_at`을 기록한다. 이후 재시도에서도 해당 입력을 수정하지 않는다.
- `draw_candidates.input_order`는 제거한다. 현재 명세는 동일 실행의 무작위 결과 재현을 요구하지 않으며, 후보 입력 순서를 별도 컬럼으로 보존할 근거를 확인하지 못했다.
- `draw_candidates`의 `entry_snapshot`과 `eligibility_snapshot`은 유지한다. 구체적인 JSON 필수 키는 ERD 검토에서 확정하지 않고 구현 시 정한다.
- 응모권 미사용 이벤트 후보는 `ticket_count=0`, `weight=1`로 저장한다. 이는 모든 후보의 동일한 적용 가중치를 표현하는 것이며, 응모권 사용 이벤트의 가중치 계산식을 확정한 뜻은 아니다.
- `draw_results`는 후보 부족으로 비는 자리도 `UNFILLED` 행으로 보존한다. 해당 행의 `candidate_id`, `selection_order`, `publication_status`는 NULL로 둔다.
- `draw_results.publication_status=EXCLUDED`는 유지한다. 이미 선정된 결과를 사후에 현재 유효한 당첨에서 제외했다는 의미로 사용한다. 당첨 취소 기록을 만들 때 해당 상태를 함께 갱신해 불일치를 막는 방향을 선택했다. 공개 명단인 `current_awards`의 갱신 시점은 아직 결정하지 않았다.
