## 고민과 판단

- 정상 접수·차감·원장 롤백과 독립 트랜잭션의 거절 이력 보존을 구분했다. 실패 직전 flush한 실제 응모·SPENT 티켓·USE 원장을 확인한다.
- 양방향 경합은 latch로 서비스 실행 위치를 제어하고 performance_schema.data_lock_waits/data_locks에서 이벤트 PRIMARY의 S/X 대기를 확인한다. 일정 시간 대기를 성공 근거로 사용하지 않는다.

- 공용 마감 정책은 DB 트랜잭션 확정 시점이다. EntryRecorder의 최종 시각 검사 후 beforeCommit에서 마감이 되는 경우 오류 없이 ACCEPTED가 확정되는 결함을 재현했다. 응모 담당 D 영역이며 사용자에게 수정 범위를 확인 중이다. 실패 테스트는 삭제·비활성화하지 않았다.

## 확인 결과 / 막힌 점

- 첫 관련 테스트 시도: 공통 flock 사용, Java 부재로 Gradle 시작 전 실패.
