## 오늘 한 일

- GD-56 추첨 후보·경품·선정 결과 모델을 `record`에서 클래스로 바꾸고 접근자를 getter로 변경했다. 선정 결과의 중첩 enum은 별도 `DrawSelectionResultType` 파일로 분리했다. 추첨 서비스와 테스트의 호출부도 함께 수정했다.
- 백엔드 [코드 스타일](../../01-conventions/code-style.md)에 `core` 도메인 클래스와 enum 배치, `@AllArgsConstructor`·`@Builder`·`toString()`·JSON API DTO의 `record` 사용 규칙을 기록했다.
- [PR #5](https://github.com/GETDDO/getddo-be/pull/5)가 `dev`에 병합된 뒤, 세 추첨 도메인 클래스의 `toString()` 재정의를 제거했다. 이 후속 수정은 [PR #17](https://github.com/GETDDO/getddo-be/pull/17)로 분리했다.
- `feat/GD-56`에 최신 `origin/dev`를 충돌 없이 병합하고 원격 브랜치에 푸시했다. 10월 1일 확인 당시 `dev` 대비 PR #17의 변경은 세 파일에서 17줄을 제거한 내용이었다.

## 고민과 판단

- 현재 추첨 입력·결과 모델에는 상태 변경 동작이 없어 클래스 전환 후에도 `private final` 필드와 값 비교 동작을 유지했다. enum 분리와 `toString()` 제거는 새 코드 스타일 규칙에 맞췄다.
- 이미 병합된 PR #5를 수정할 수 없어 후속 코드 스타일 정리를 별도 PR로 만들었다. 원격에 공개된 수정 커밋을 다시 작성하지 않고 최신 `dev`를 병합했다.
