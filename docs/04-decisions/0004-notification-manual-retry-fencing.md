# ADR-0004: 알림 수동 복구 구간과 누적 선점 차수 분리

- 상태: 제안
- 작성자 / 날짜: AI 초안 / 2026-10-12
- 검토자: 전민규 확인 대기
- 관련 작업 기록 / PR: GD-72, PR 미생성
- 대체한 ADR / 대체된 ADR: 해당 없음

## 배경

기존 알림 워커는 누적 시도 횟수를 자동 재시도 한도와 선점 차수 보호에 함께 사용한다. 관리자 복구 때 횟수를 0으로 초기화하면 예전 워커와 새 워커의 차수가 같아져 늦게 도착한 완료·실패 기록이 새 처리를 덮어쓸 수 있다.

발송 상태 PENDING은 미선점 대기와 선점 중 모두 사용된다. 복구 접수 직후 아직 새 워커가 선점하지 않아도 예전 발송 워커의 차수가 남아 있으므로 누적 차수 비교만으로는 충분하지 않다.

## 결정과 이유

사용자가 승인한 누적 차수 유지 방향을 다음과 같이 구현했다.

- notification_jobs.attempt_base, notifications.delivery_attempt_base를 새 마이그레이션 V019로 추가한다. 기존 행의 기본값은 0이다.
- 수동 복구 접수 때 현재 누적 차수를 기준 차수에 저장한다. 누적 차수 자체는 되돌리지 않는다.
- 워커는 누적 차수를 증가시키고, 자동 재시도 횟수는 누적 차수 - 기준 차수로 계산한다.
- 사용자별 생성과 완료·실패 갱신에는 누적 차수·기준 차수·상태를 함께 검사한다. 특히 발송 복구 직후 예전 워커의 콜백도 기준 차수 불일치로 거절한다.
- 복구 접수와 감사 기록은 Service 트랜잭션에서 함께 확정한다. 조회·상태 검사는 저장소에 두고 권한·시점·최종 실패 허용 조건은 Service·도메인에 둔다.
- 생성 복구는 GD-70과 동일한 이벤트 → 작업 잠금 순서를 사용한다. 직접 API 호출의 복구 트랜잭션은 READ_COMMITTED로 설정한다.

## 검토한 대안

- 횟수 초기화: 오래된 워커와 새 선점 차수가 충돌하므로 사용하지 않았다.
- 누적 횟수만 유지: 재시도 한도가 과거 구간까지 누적되고, 발송 복구 직후의 예전 콜백을 구분할 기준이 없으므로 기준 차수를 추가했다.
- 별도의 UUID 선점 토큰: 사용할 수 있지만 기존 워커 모델·컬럼을 더 크게 바꾸므로 이번에는 기존 차수 보호를 확장했다.

## 영향과 재검토 조건

- 관리자 응답의 횟수는 누적 차수다. 복구 후 다시 0으로 보이지 않으며 자동 재시도 구간과 구분해 설명한다.
- Java int 최대 차수에서는 추가 복구·선점을 거절하거나 최종 실패로 정리하여 오버플로를 막는다.
- 구버전 워커는 새 기준 차수 조건을 모르므로 V019와 새 워커 코드를 전체 실행 인스턴스에 적용한 뒤 관리자 수동 복구를 사용해야 한다.
- HTTP·동시 복구·롤백·구간 재시도·늦은 발송 콜백 회귀 테스트를 작성했다. 이번 구현의 테스트 소스 컴파일은 성공했지만 테스트 실행 결과는 아직 확인하지 않았다.
- 운영 배포 순서·자동 재시도 간격 변경·대규모 조회 성능은 해당 요구가 생기면 재검토한다. 공용 실패 정책과 API 계약은 getddo-spec을 기준으로 한다.
