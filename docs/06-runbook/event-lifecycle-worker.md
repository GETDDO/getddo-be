# 이벤트 모집 상태 워커 확인 — GD-203

- 상태: 검토 대기 — 담당자 확인 전
- 구현·트랜잭션: [이벤트 상태 전환과 감사 기록](../02-api/event-lifecycle-and-audit.md)

## 설정과 정상 동작

- `getddo.event.lifecycle-worker.enabled`: 기본 true. false이면 워커를 생성하지 않는다.
- `getddo.event.lifecycle-worker.poll-delay`: 기본 1000ms, 이전 폴링 완료 후 다음 실행까지의 간격이다.
- 폴링당 최대 20개를 처리한다. 처리 시각은 저장된 시각과 같은 UTC 기준이며 정각부터 전환 대상이다.
- 삭제되지 않은 `SCHEDULED`·`OPEN`만 읽으며 잠긴 이벤트는 건너뛴다. 여러 인스턴스는 각자의 트랜잭션에서 잠금을 얻은 묶음을 처리한다.

상태 반영은 비동기이므로 정확히 시작·마감 시각에 응답이 바뀐다고 보장하지 않는다. 기존 응모·수정의 서버 시각 검증은 계속 적용된다. 모집 상태 전환은 자동 추첨·수동 발표와 별개다.

## 실패와 복구

`Event lifecycle update deferred: failureType=...` 로그는 한 묶음의 실패를 나타낸다. 해당 트랜잭션의 상태·감사 기록은 함께 롤백되고 다음 폴링이 같은 조건을 재검사한다. 실패한 호출에서 일부 상태만 확정하지 않는다.

상태 지연이 지속되면 워커 활성화 여부, 애플리케이션 스케줄러 실행, DB 연결·장기 트랜잭션, 감사 저장 오류를 확인한다. 원인을 해결하면 다음 폴링에서 경과한 시각을 반영한다. 서버 중단 중 모집이 전부 끝난 SCHEDULED도 CLOSED로 복구한다. 감사 행을 임의 삭제하거나 상태를 수동 덮어써 복구하지 않는다.

마감 +5분이 지나도 추첨이 실행되지 않으면 모집 상태 확인 후 [추첨 실행 복구](draw-execution-recovery.md)를 따른다. 결과 공개는 관리자 수동 요청 대상이며 이 워커가 자동으로 공개하지 않는다.
